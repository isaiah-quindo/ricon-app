HOW TO USE
----------
1. In Supabase Dashboard → Database → Backups, click "Backup now" on the prod
   project and wait for it to finish.
2. Open Supabase Studio → SQL Editor → New query.
3. Paste the MIGRATION BLOCK below → Run.
4. Paste the VERIFICATION BLOCK below → Run → confirm expected results.
5. Deploy the updated app code so the new columns are used.

If anything fails, the BEGIN/COMMIT wrapper rolls the entire change back — you
will not end up half-applied.

BEGIN;

-- 1. Create the discount_codes table
CREATE TABLE "discount_codes" (
    "id"                  uuid          NOT NULL PRIMARY KEY,
    "code"                varchar(255)  NOT NULL,
    "race_category_id"    uuid          NOT NULL,
    "discount_percentage" decimal(5, 2) NOT NULL,

    CONSTRAINT "discount_codes_code_unique" UNIQUE ("code"),

        FOREIGN KEY ("race_category_id")

-- 2. Add discount columns to the registrations table
ALTER TABLE "registrations" ADD COLUMN "discount_code_id" uuid NULL;
ALTER TABLE "registrations" ADD COLUMN "discount_amount"  decimal(10, 2) NULL;
ALTER TABLE "registrations" ADD CONSTRAINT "registrations_discount_code_id_foreign"
    FOREIGN KEY ("discount_code_id")

-- 3. Tell Laravel both migrations have been applied so a future `migrate`

WITH next_batch AS (SELECT COALESCE(MAX(batch), 0) + 1 AS b FROM migrations)
INSERT INTO migrations (migration, batch)
SELECT '2026_05_20_223149_create_discount_codes_table', b FROM next_batch
UNION ALL
SELECT '2026_05_20_223150_add_discount_fields_to_registrations_table', b FROM next_batch;

COMMIT;

================================================================================
NOTES
================================================================================
- `unsignedInteger` in Laravel migrations maps to `integer` on Postgres
  (Postgres has no unsigned integer type). The dev DB uses the same
  translation, so prod will match dev.
- The `after('...')` calls in the Laravel migrations are silently ignored by
  Postgres (no column ordering), so `discount_code_id` and `discount_amount`
  will land at the end of `registrations`. Harmless.
- The migration filenames inside the INSERT INTO migrations (...) statement
  must match exactly — no `.php` suffix.
